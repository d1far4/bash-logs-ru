# Разбор логов в Linux: 15 задач с решениями на bash, grep, awk, sort и uniq

15 задач по разбору логов от простых к сложным: `grep`, `cut`, `sort`, `uniq`, `sed`, `awk` и небольшой скрипт на `bash` с `while read`, `if` и `case`. Данные — суточные логи маленького книжного интернет-магазина: 120 запросов nginx, 59 записей журнала приложения и выгрузка заказов в CSV (40 строк, одна из них дубль). Решение каждой задачи — однострочный конвейер или короткий скрипт, и все они проверяются скриптом [`check.py`](check.py).

У каждой задачи есть решение под спойлером, ожидаемый вывод и разбор типичной ошибки. Решения написаны без расширений GNU (`grep -P`, функции `gawk`, `sort -V`), чтобы одинаково работать в Linux и в простых реализациях `awk`; единственное исключение из стандарта POSIX — `grep -o`, он есть в GNU, BSD и BusyBox.

## Как получить данные

```
git clone https://github.com/d1far4/bash-logs-ru && cd bash-logs-ru
```

Если `git` не установлен, скачайте три файла ([`access.log`](data/access.log), [`app.log`](data/app.log), [`orders.csv`](data/orders.csv)) и положите их в папку `data` рядом с тем местом, откуда запускаете команды. Подойдёт любой терминал Linux или macOS, WSL или Git Bash в Windows. Все команды в задачах выполняются из корня репозитория и обращаются к файлам по путям вида `data/access.log`.

Файлы создаёт скрипт [`gen_data.py`](gen_data.py) (только стандартная библиотека Python, фиксированное зерно), поэтому у всех получаются одинаковые данные.

## Данные

| Файл | Что внутри | Строк |
|---|---|---|
| `data/access.log` | журнал nginx в формате combined: запросы к магазину за 14 марта 2026 года | 120 |
| `data/app.log` | журнал приложения: `дата время УРОВЕНЬ [модуль] сообщение`, уровни DEBUG, INFO, WARN, ERROR, модули `payment`, `orders`, `catalog`, `mailer`, `auth` | 59 |
| `data/orders.csv` | выгрузка заказов: `id;date;city;customer;amount;status`, статусы `paid`, `cancelled`, `refunded` | 41 (заголовок и 40 заказов) |

Что важно знать заранее. Если делить строку `access.log` по пробелам (так по умолчанию делает `awk`), то `$1` — IP-адрес, `$4` — время вместе с `[`, `$7` — путь с параметрами, `$9` — статус, `$10` — размер ответа в байтах. У шести ответов 304 размер записан не числом, а знаком `-`. User-Agent содержит пробелы, поэтому его удобнее брать, разделив строку по кавычкам: тогда он шестое поле. В `app.log` после даты и времени идёт уровень (`$3`) и модуль в квадратных скобках (`$4`); короткие уровни дополнены пробелами до пяти символов, поэтому между `INFO` и `[payment]` два пробела. В `orders.csv` разделитель `;`, как в выгрузках из русского Excel, суммы целые, в рублях. У заказа 10445 город не указан, а строка заказа 10447 повторена в конце файла. Все файлы в UTF-8 с переводами строк LF.

Пробуйте решать сами, прежде чем открывать спойлер. Порядок строк в ответе задан в условии: без явной сортировки с понятным правилом для равных значений результат не воспроизводится.

## Простые: считаем и фильтруем

### Задача 1. Сколько данных

Выведите три строки вида `файл число`: сколько запросов в `access.log`, сколько записей в `app.log` и сколько строк с заказами в `orders.csv` (без строки заголовка), именно в таком порядке.

<details><summary>Решение</summary>

```bash
echo "access.log $(wc -l < data/access.log | tr -d ' ')"
echo "app.log $(wc -l < data/app.log | tr -d ' ')"
echo "orders.csv $(tail -n +2 data/orders.csv | wc -l | tr -d ' ')"
```

Ожидаемый вывод:

```text
access.log 120
app.log 59
orders.csv 40
```

**Типичная ошибка:** написать `wc -l data/orders.csv`. Получится 41 вместо 40: заголовок тоже строка. К тому же `wc` с именем файла печатает `41 data/orders.csv`, а не одно число. Если подать файл через `<`, имени у `wc` нет и он выводит только число; `tr -d ' '` убирает отступ, которым `wc` в macOS выравнивает число.

</details>

### Задача 2. Ответы 5xx

Выведите IP, путь и статус каждого запроса, на который сервер ответил кодом 5xx, в порядке следования в журнале, поля через пробел.

<details><summary>Решение</summary>

```bash
grep -E '" 5[0-9][0-9] ' data/access.log | cut -d' ' -f1,7,9
```

Ожидаемый вывод:

```text
203.0.113.58 /cart 500
198.51.100.9 /login 502
192.0.2.44 /api/orders 502
192.0.2.44 /checkout 502
192.0.2.44 /checkout 500
203.0.113.7 /cart 500
```

**Типичная ошибка:** `grep 500 data/access.log`. Шаблон ищется по всей строке, а «500» встречается где угодно: в пути (`/book/500-russian-proverbs`, `/book/500-missing`) и в размере ответа (`12500`, `25001`). В журнале такой запрос возвращает 7 строк, из них 4 лишние, и при этом пропускает все три ответа 502. Шаблон `" 5[0-9][0-9] ` привязывает цифры к месту сразу после закрывающей кавычки запроса, то есть к полю статуса. То же через `awk`, где поле выбирается явно: `awk '$9 >= 500 { print $1, $7, $9 }' data/access.log`.

</details>

### Задача 3. Запросы по статусам

Посчитайте запросы по статусам. Выведите `статус число`: сначала статусы с большим числом запросов, при равенстве числа по возрастанию статуса.

<details><summary>Решение</summary>

```bash
awk '{ print $9 }' data/access.log | sort | uniq -c | awk '{ print $2, $1 }' | sort -k2,2nr -k1,1
```

Ожидаемый вывод:

```text
200 95
404 7
301 6
304 6
500 3
502 3
```

**Типичная ошибка:** закончить конвейер на `sort -rn`. У строк с одинаковым числом `sort` сравнивает строки целиком, и ключ `-r` разворачивает и это сравнение: 304 окажется выше 301, а 502 выше 500. Ответ формально верен, но порядок равных строк получается «наоборот», и результат нельзя сравнить с эталоном. Явная пара ключей `-k2,2nr -k1,1` (число по убыванию, затем статус по возрастанию) задаёт порядок однозначно.

</details>

## Средние: группируем и считаем

### Задача 4. Пять самых активных IP

Выведите пять IP-адресов с наибольшим числом запросов в формате `ip число`. При равенстве числа адреса идут по возрастанию как строки.

<details><summary>Решение</summary>

```bash
export LC_ALL=C
awk '{ print $1 }' data/access.log | sort | uniq -c | awk '{ print $2, $1 }' | sort -k2,2nr -k1,1 | head -5
```

Ожидаемый вывод:

```text
198.51.100.23 15
203.0.113.7 15
192.0.2.44 10
192.0.2.101 8
198.51.100.9 8
```

**Типичная ошибка:** убрать первый `sort`. `uniq -c` склеивает только соседние одинаковые строки, а запросы одного адреса разбросаны по всему дню: вместо 15 запросов получатся короткие серии, и больше 3 такая команда не покажет. Вторая ловушка в том, что на границе пятого места равны три адреса по 8 запросов, а `head -5` оставит двух. Кто из них попадёт в ответ, решает второй ключ сортировки, поэтому он обязателен. `LC_ALL=C` сравнивает адреса по байтам, и порядок одинаков на любой машине.

</details>

### Задача 5. Самые частые пути без параметров

Выведите пять самых частых путей из `access.log` без части после `?` в формате `путь число`. При равенстве числа пути идут по возрастанию.

<details><summary>Решение</summary>

```bash
export LC_ALL=C
awk '{ print $7 }' data/access.log | cut -d'?' -f1 | sort | uniq -c | awk '{ print $2, $1 }' | sort -k2,2nr -k1,1 | head -5
```

Ожидаемый вывод:

```text
/catalog 23
/login 12
/cart 10
/ 7
/book/the-hobbit 6
```

**Типичная ошибка:** не отрезать параметры. `/catalog`, `/catalog?page=2` и `/catalog?sort=price` считаются тремя разными страницами, и `/catalog` с 11 запросами оказывается на втором месте после `/login` с 12, хотя на самом деле каталог запрашивали 23 раза. Параметры отрезает `cut -d'?' -f1` или `sed 's/?.*//'`.

</details>

### Задача 6. Запросы по часам

Посчитайте запросы по часам. Выведите `час число`, где час состоит из двух цифр, от 00 до 23, по возрастанию часа.

<details><summary>Решение</summary>

```bash
cut -d: -f2 data/access.log | sort | uniq -c | awk '{ print $2, $1 }'
```

Ожидаемый вывод (первые 8 строк из 24; полный вывод, с которым сверяет `check.py`, лежит в файле [`expected/task06.txt`](expected/task06.txt)):

```text
00 2
01 1
02 1
03 2
04 1
05 1
06 2
07 4
```

**Типичная ошибка:** вырезать час по номерам символов, например `cut -c29-30`. Время стоит после IP-адреса, а длина адреса меняется от 9 до 14 символов, поэтому фиксированная позиция попадает на час только у адресов одной длины, у остальных вырезаются кусочки даты, двоеточия и минуты. Режьте по разделителю: первое двоеточие в строке стоит сразу после года, поэтому второе поле при разделителе `:` и есть час (`cut -d: -f2`).

</details>

### Задача 7. Сумма и средний размер ответа

Выведите две строки: `total=<сумма отданных байт по всем запросам>` и `average=<средний размер ответа с одним знаком после запятой>`. Среднее считайте только по ответам, у которых размер указан числом.

<details><summary>Решение</summary>

```bash
awk '$10 != "-" { total += $10; n++ } END { printf "total=%d\naverage=%.1f\n", total, total / n }' data/access.log
```

Ожидаемый вывод:

```text
total=1599393
average=14029.8
```

**Типичная ошибка:** делить на число всех строк (`NR`). У шести ответов 304 вместо размера стоит `-`. `awk` в сумме считает его нулём, поэтому итог не меняется, но эти строки попадают в знаменатель, и среднее занижается: 13328.3 вместо 14029.8.

</details>

Выведите из `app.log` строки уровня ERROR модуля `payment`, как есть, в порядке следования.

Уровень и модуль занимают третье и четвёртое поля, их и нужно сравнивать.

</details>

### Задача 9. Номера заказов из журнала

Выведите номера заказов, которые встречаются в `app.log` в виде `order=число`, каждый один раз, по возрастанию.

<details><summary>Решение</summary>

```bash
grep -o 'order=[0-9][0-9]*' data/app.log | cut -d= -f2 | sort -n | uniq
```

Ожидаемый вывод (первые 8 строк из 11; полный вывод, с которым сверяет `check.py`, лежит в файле [`expected/task09.txt`](expected/task09.txt)):

```text
10430
10435
10438
10441
10443
10445
10447
10448
```

**Типичная ошибка:** написать шаблон `order=[0-9]*`. Звёздочка допускает ноль цифр, поэтому запись `order=n/a` даёт совпадение `order=`, и в начале списка появляется пустая строка. Нужна хотя бы одна цифра: `[0-9][0-9]*`. Кроме того, `grep -o` печатает каждое совпадение отдельной строкой (запись о слиянии заказов 10448 и 10449 даёт два номера), а повторяющиеся номера схлопывает только `uniq` после сортировки.

</details>

### Задача 10. Среднее и максимум took

Найдите в `app.log` все значения вида `took=число` (миллисекунды) и выведите три строки: `count=` — сколько их, `avg=` — среднее с одним знаком после запятой, `max=` — наибольшее.

<details><summary>Решение</summary>

```bash
grep -o 'took=[0-9][0-9]*' data/app.log | cut -d= -f2 | awk '{ sum += $1; if ($1 > max) max = $1 } END { printf "count=%d\navg=%.1f\nmax=%d\n", NR, sum / NR, max }'
```

Ожидаемый вывод:

```text
count=25
avg=2408.8
max=30004
```

**Типичная ошибка:** искать максимум как `sort | tail -1`. Без `-n` `sort` сравнивает значения как текст, и `88` оказывается «больше» `30004`, потому что `8` в таблице символов идёт после `3`. В этих данных такая команда выдаёт 88 вместо 30004. Для чисел нужен `sort -n` или сравнение внутри `awk`, как в решении.

</details>

### Задача 11. Боты и остальные

Разделите запросы из `access.log` на сделанные ботами и остальными. Бот это запрос, в User-Agent которого есть `bot` в любом регистре. Выведите две строки: `bots число` и `others число`.

<details><summary>Решение</summary>

```bash
awk -F'"' '{ if (tolower($6) ~ /bot/) bots++; else others++ } END { printf "bots %d\nothers %d\n", bots, others }' data/access.log
```

Ожидаемый вывод:

```text
bots 15
others 105
```

**Типичная ошибка:** `grep -c bot data/access.log`. Команда ищет по всей строке и с учётом регистра. Она находит три запроса обычных посетителей к `/book/robotics-for-beginners` (в `robotics` есть `bot`) и пропускает два запроса `AhrefsBot`, где `Bot` с заглавной: получается 16 вместо 15. Добавление `-i` вернёт `AhrefsBot`, но число вырастет до 18. Разделите строку по кавычкам (`-F'"'`): шестое поле это User-Agent, и искать нужно только в нём.

</details>

## Сложнее: CSV, скрипт, два файла

### Задача 12. Выручка по городам из CSV

Посчитайте выручку по городам для заказов со статусом `paid`. Выведите `сумма город`: сначала города с большей выручкой, при равенстве по названию. Заказы с пустым городом покажите как `(без города)`.

<details><summary>Решение</summary>

```bash
export LC_ALL=C
awk -F';' 'NR > 1 && $6 == "paid" { city = $3; if (city == "") city = "(без города)"; sum[city] += $5 }
           END { for (city in sum) print sum[city], city }' data/orders.csv | sort -k1,1nr -k2
```

Ожидаемый вывод:

```text
30970 Москва
23060 Нижний Новгород
18870 Казань
9870 Екатеринбург
8750 Новосибирск
4740 Санкт-Петербург
4020 Краснодар
1450 (без города)
```

**Типичная ошибка:** выбрать «всё, кроме отменённых» (`$6 != "cancelled"`) и забыть `NR > 1`. Заголовок тоже «не отменён», и в отчёте появляется строка `0 city`; возвращённый заказ 10416 попадает в выручку, и Москва вместо 30970 получает 39000. Вторая ловушка: пустой город без замены становится ключом из пустой строки, и строка отчёта выглядит как `1450` без названия. Для выручки фильтруйте по нужному значению (`== "paid"`), а не вычитайте лишнее.

</details>

### Задача 13. Дубли строк в CSV

Найдите в `orders.csv` строки, которые встречаются больше одного раза. Выведите каждую такую строку один раз.

<details><summary>Решение</summary>

```bash
sort data/orders.csv | uniq -d
```

Ожидаемый вывод:

```text
10447;2026-03-14;Новосибирск;Сидоров К.;3100;cancelled
```

**Типичная ошибка:** применить `uniq -d` к файлу как есть. `uniq` сравнивает только соседние строки, а дубль заказа 10447 стоит в конце файла, далеко от оригинала: `uniq -d data/orders.csv` ничего не выведет. Сначала `sort`, чтобы одинаковые строки встали рядом. Учтите и обратное: совпадение строки целиком не поймает повтор одного `id` с другой суммой, для этого сравнивайте только первое поле: `cut -d';' -f1 data/orders.csv | sort | uniq -d`.

</details>

### Задача 14. Скрипт: классы статусов и тревога

Напишите скрипт, который читает `access.log` построчно и считает ответы 2xx, 3xx, 4xx и 5xx. Выведите четыре строки `2xx число`, ..., `5xx число`, а затем `ALERT: 5xx=<число> > 5`, если ответов 5xx больше пяти, или `OK`, если нет.

<details><summary>Решение</summary>

```bash
c2=0; c3=0; c4=0; c5=0
limit=5
while read -r _ _ _ _ _ _ _ _ status _; do
  case "$status" in
    2??) c2=$((c2 + 1)) ;;
    3??) c3=$((c3 + 1)) ;;
    4??) c4=$((c4 + 1)) ;;
    5??) c5=$((c5 + 1)) ;;
  esac
done < data/access.log
echo "2xx $c2"
echo "3xx $c3"
echo "4xx $c4"
echo "5xx $c5"
if [ "$c5" -gt "$limit" ]; then
  echo "ALERT: 5xx=$c5 > $limit"
else
  echo "OK"
fi
```

Ожидаемый вывод:

```text
2xx 95
3xx 12
4xx 7
5xx 6
ALERT: 5xx=6 > 5
```

**Типичная ошибка:** подать файл в цикл через конвейер: `awk '{ print $9 }' data/access.log | while read -r s; do ...; done`. Каждая часть конвейера в bash по умолчанию работает в подоболочке, поэтому счётчики, которые менял цикл, после `done` снова равны нулю: скрипт напечатает `5xx 0` и `OK`, хотя ошибки были. Читайте файл перенаправлением `done < data/access.log`, тогда цикл выполняется в основной оболочке. В `read` восемь первых полей отбрасываются в `_`, девятое попадает в `status`, остаток строки уходит в последний `_`.

</details>

### Задача 15. Два файла: ошибки и города заказов

Для заказов, которые упомянуты в строках уровня ERROR файла `app.log`, найдите в `orders.csv` город, сумму и статус. Выведите `id;город;сумма;статус` по возрастанию `id`, каждый заказ один раз, пустой город замените на `-`.

<details><summary>Решение</summary>

```bash
awk '
  FNR == NR {
    if ($3 == "ERROR")
      for (i = 4; i <= NF; i++)
        if ($i ~ /^order=[0-9]+$/) err[substr($i, 7)] = 1
    next
  }
  FNR > 1 && ($1 in err) && !($1 in seen) {
    seen[$1] = 1
    city = $3; if (city == "") city = "-"
    print $1 ";" city ";" $5 ";" $6
  }
' data/app.log FS=';' data/orders.csv | sort -t';' -k1,1n
```

Ожидаемый вывод:

Если задать `-F';'` для всей команды, строки `app.log` не разобьются по пробелам, `$3` не окажется уровнем, и результат будет пустым. Присваивание `FS=';'` между именами файлов вступает в силу, когда `awk` доходит до второго файла. Заказа 10452 в ответе нет: он есть в журнале, но ещё не попал в выгрузку, и при таком сопоставлении такие заказы пропадают молча.

## Главные ловушки

**Ищите по полю, а не по подстроке.** `grep 500` находит «500» в пути и в размере ответа, `grep bot` — в пути `/book/robotics-for-beginners`, а `grep ERROR | grep payment` — в тексте сообщений других модулей. Выберите поле (`$9`, `$3 == "ERROR"`, шестое поле при разделителе `"`) или привяжите шаблон к соседним символам (задачи 2, 8 и 11).

**`uniq` видит только соседние строки.** Перед `uniq` всегда нужен `sort`: иначе `uniq -c` посчитает только подряд идущие повторы, а `uniq -d` не найдёт дубль, стоящий далеко от оригинала (задачи 4 и 13).

**Порядок равных значений задавайте явно.** `sort -rn` разворачивает и сравнение равных строк, поэтому 304 окажется выше 301. Пишите отдельные ключи: `sort -k2,2nr -k1,1`. С `head -5` без второго ключа на границе окажется произвольный адрес (задачи 3, 4, 5 и 12).

**Ставьте `LC_ALL=C`, когда важен порядок или байты.** В локали `C` строки сравниваются по байтам, и результат одинаков на любой машине; в других локалях действуют словарные правила, и порядок строк с точками, дефисами и кириллицей может отличаться от сервера к серверу (задачи 4, 5 и 12). Цена в том, что символ становится байтом: `cut -c` и `awk` с `length` считают кириллическую букву за два байта. Поэтому поля режут по разделителю (`cut -d`, `-F`), а не по позициям символов (задача 6).

**Числа, пропуски и шаблоны.** `sort` без `-n` сравнивает числа как текст: `88` «больше» `30004` (задача 10). Знак `-` вместо размера в `awk` равен нулю в сумме, но не должен попадать в знаменатель среднего (задача 7). Шаблон `[0-9]*` допускает ноль цифр, нужен `[0-9][0-9]*` (задача 9).

**Заголовок, пустые поля, дубли и подоболочки.** `wc -l` считает и заголовок CSV (задача 1), заголовок нужно пропускать явно, а пустой город — это пустой ключ, который стоит заменить на понятную метку (задачи 12 и 15). Дубль строки в данных удваивает результат, если не отфильтровать повтор (задача 15). Цикл `while read` после конвейера работает в подоболочке и теряет счётчики (задача 14).
